# ADR-IMAGE-RAG-001 · 이미지 중복 판정과 활용 검색의 분리

- 날짜: 2026-09-04
- 상태: **Accepted — 사용자가 아래 운영 순서를 명시적으로 승인**
- 범위: 이미지 RAG의 입고·중복 확인·Luna 분석·검색 표현. 설계 승인이지 새 추론·삭제·배포 승인은 아니다.
- 적용: 이후 이 레인을 다루는 에이전트는 [AGENTS.md](../AGENTS.md)의 실행 경계와 함께 준수한다.

## 맥락과 결정 이유

목적은 이미지를 모으는 것 자체가 아니라, 나중에 “어디에 어떻게 쓸 수 있는가”로 찾고 서로 다른 디자인 대안을 선택하는 것이다. 동일 이미지가 반복 노출되면 안 되고, BST처럼 같은 형식의 변형은 대표 한 장 아래에서 펼쳐봐야 한다. 반면 같은 활용 목적의 서로 다른 디자인은 검색 선택지로 유지해야 한다.

따라서 “이미지가 같은가/닮았는가”와 “같은 작업에 쓸 수 있는가”를 하나의 점수에 맡기지 않는다. 원문 프롬프트는 의도이며 실제 결과와 다를 수 있고, LLM 활용 제안은 해석이며 시각적 동일성의 증거가 아니다. 확정 중복을 먼저 제외하면 불필요한 이미지 임베딩·LLM 분석을 줄일 수 있다.

## 결정한 순서

```text
입고 · 출처/권리 기록 · 파일/픽셀/프롬프트 해시 계산
    ↓
확정 중복 제외 — 원문과 출처 관계는 보존
    ↓
이미지 임베딩 → 유사 후보 탐색
    ↓
사람 확인: 동일 제외 / 형식별 그룹 / 개별 유지
    ↓
유지할 이미지 + 원문 → Luna 분석
    ↓
활용 중심 텍스트 임베딩
```

- 기계 확정은 현재 보수적 정책 `exact_file OR (exact_pixels AND nonblank_prompt_exact)`를 사용한다. `exact_file`은 프롬프트가 달라도 확정 일치다. 파일 해시는 다르고 픽셀만 같지만 프롬프트가 다른 경우, 또는 프롬프트만 같은 경우는 사람 확인 대상으로 남긴다. 과거 실험 구현이 모두 이 규칙이었다고 소급해 주장하지 않는다.
- SHA-256은 일치 확인이며 “80% 유사” 점수가 아니다. perceptual hash·코사인은 후보 신호일 뿐 삭제 확률이 아니다.
- 제외는 기본 노출/추론에서의 논리 제외다. 원문·권리·출처·대표 계보를 보존하며 물리 삭제는 별도 승인한다.
- 확정된 동일 관계, 형식별 변형 그룹, 활용 태그를 구분한다. 그룹 대표만 화면에 표시하되 서로 다른 멤버의 자산·벡터는 유지한다.
- 사람 검토를 거친 유지 이미지에 대해 Luna 관찰/분석을 만든다. 같은 프롬프트·그룹이라는 이유로 다른 이미지의 시각 설명을 무검증 상속하지 않는다. 선택 메모가 없다는 이유로 이미지 승인을 막지 않는다.
- 메타데이터 기술 검증/QA와 이미지 승인, 메타데이터 사람 검수, 권리·공개 승인은 별도다. QA로 제외된 필드를 원문으로 몰래 대체하지 않으며 안전한 검색 입력이 비면 보류한다.

## 이미지·텍스트 표현 계약

| 표현 | 입력과 의미 | 역할 |
|---|---|---|
| 원자료 | 정확한 이미지, 원문 프롬프트, 사람 메모, 출처·권리 | 보존·설명·복사·감사 |
| 이미지 벡터 | 이미지-only 입력; 현재 공용 캐시는 Voyage multimodal 3.5 / 1024D로 기록 | 시각 유사 후보 |
| 텍스트 벡터 | 선별된 시각 메타데이터 + **분석된** 프롬프트 의도/고정 조건/슬롯 + 메모; 현재 Voyage 4-lite / 512D | 활용 중심 검색 |

“이미지에서 얻은 정보가 간접적으로 들어간 텍스트 임베딩”은 별도 종류의 임베딩을 뜻하지 않는다. **이미지 → Luna가 텍스트로 기술 → 텍스트 임베딩**이라는 정보 전달 경로다. 사용자 표현인 “LLM 메타데이터 text + prompt + 메모”와 종류는 같지만, prompt가 원문 전체를 뜻한다면 현행 입력과는 다르다. 현재는 원문 전체를 붙이지 않고 분석을 거쳐 선별한 의미만 포함한다.

실제 경로는 [compact_projection](../src/image_rag_eval/embedding_budget.py)이다. 원문 전체 + 분석 JSON + 메모는 비교용 naive 입력 정의로 보존했고, 전체 377개는 compact 입력으로 실행했다. 원문 고유 표현·세부 규칙이 요약에서 빠질 위험은 남는다. 원문 보존이 의미 검색의 누락을 자동 해결하는 것은 아니다. 원문 전체 포함 여부를 바꾸려면 검색 영향·추가 비용을 검토하고 새 입력 버전으로 별도 실행한다.

## 고려한 대안과 손익

| 대안 | 이점 | 채택 여부와 이유 |
|---|---|---|
| 이미지-only 하나로 모든 작업 | 텍스트 해석 오류에 덜 의존, 구조 단순 | 활용 의도·사람 메모를 충분히 반영하지 못하므로 단독 채택하지 않음 |
| 메타데이터 먼저 → 이미지+메타데이터+원문 통합 벡터 | 시각과 언어의 상호작용을 함께 표현, 후보 설명을 먼저 제공 | 통합 검색 품질은 개선될 수 있으나, 제외될 이미지에도 LLM 비용 발생; 설명 변경 시 통합 벡터 재생성; 중복 판정과 활용 유사성이 섞일 위험 때문에 기본안으로 채택하지 않음 |
| 확정 중복·사람 검토 먼저 → 이미지/텍스트 벡터 분리 | 비용 절감, 원인 추적, 텍스트 변경 시 이미지 벡터 유지 | **채택**. 두 벡터의 버전/캐시 관리가 필요하고 텍스트 요약 손실이 있다는 단점 수용 |

통합 벡터의 품질이 나쁘다고 입증한 것은 아니다. 결정 근거는 사용자 목적·승인 경계·갱신 비용이며, 전체 검색 정확도나 특정 모델의 우월성을 증명한 결정은 아니다.

## 실행 규칙과 현재/미구현 구분

- 캐시 키에는 모델·차원·입력 타입·내용과 필요한 전처리/분석 버전을 묶는다. 원문·이미지·분석 계약이 바뀌면 영향받는 파생물만 새 버전으로 만든다. 메모만 바뀌면 이미지 시각 분석과 이미지 벡터는 재호출하지 않는다.
- Luna는 기본 한 turn 3개, 최대 5개. 이는 보수적 운영 선택이며 3 vs 5 정확도 A/B의 승자라는 뜻이 아니다. 분석 사용량은 검증된 session/turn 경계로 기록한다.
- 긴 작업 세션의 캐시 입력도 처리 문맥이다. 고정 prefix 효과와 대화 이력 캐시를 구분하고 문맥·비캐시 입력·출력·실패/재시도를 함께 관리한다. 세션을 무제한 연장하는 방식은 비용 최적화로 간주하지 않는다.
- 현재 저장 질의 화면은 **텍스트 검색 → 그룹별 최고 멤버 점수 → 사람 지정 대표 한 장**이다. 이미지 벡터와 텍스트 벡터의 통합 점수나 RRF가 이미 적용된 것은 아니다.
- 향후 시각 검색/복합 검색은 각각의 모델에 맞는 질의 벡터를 사용한다. 서로 다른 임베딩 공간을 직접 비교하거나 벡터/원점수를 무조건 평균하지 않는다. 필요하면 검색 순위 결합을 별도 검증한다.
- 최신 실행 증거는 [377개 임베딩 보고서](../../Reports/2026-09-04-08_Voyage_텍스트임베딩_실행과_그룹검색_검증.md), 완료 범위·사용량 설명은 [이번 결정 보고서](../../Reports/2026-09-04-09_이미지RAG_운영순서_확정과_완료범위.md)를 따른다. 숫자는 실행 시점 스냅샷이지 계속 갱신되는 정책 상수가 아니다.
- 이번 문서 변경은 기존 캐시·DB·승인 이력·미검토 자료를 변경하거나 Qdrant/서버/공개 프론트에 반영하지 않는다. 한 번에 전 단계가 자동 실행되는 통합 운영기를 완성했다는 의미도 아니다.

## 재검토 조건

사용자가 독립적으로 작성한 질의에서 활용 상위 5개의 유용성·서로 다른 그룹 수·잘못된 그룹 합침·토큰/지연을 평가한다. 요약 누락이나 시각 조건 실패가 반복되면 같은 평가 집합에서 현재 텍스트 / 이미지 / 결과 결합 / 통합 입력을 비교한다. 새 API 실험은 범위·예산을 먼저 승인받고, 장점이 입증된 경우 새 ADR로 이 결정을 대체한다. 고정 “80% 유사”나 현재 11개 출처 기반 예시 결과만으로 자동 삭제·성능 우위를 승인하지 않는다.
