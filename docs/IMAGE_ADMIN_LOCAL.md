# 이미지 관리자 — 로컬 서버

## 시작점

- 주소: `http://127.0.0.1:8964/`
- 실행기: `scripts/start_image_admin.ps1`
- 서버: `src/serve_image_admin.py`
- 전용 저장소: `data/private-research/image-rag-admin/state.sqlite3`
- 현재 묶음: `2026-09-03-incremental-review-500-v1`

화면을 파일로 직접 열지 말고 위 서버 주소를 사용한다. 같은 PC에서만 접근할 수 있다. PC 재부팅 후 자동으로 시작하는 서비스는 설치하지 않았다. 다른 PC·공개 인터넷에 노출하지 않는다.

## 검토 흐름

1. **정리 결과 확인**: 완전 중복 검사와 이전 사람의 동일 판정으로 제외한 기록을 확인한다.
2. **동일 이미지 확인**: 묶음을 비교하고 같은 최종 이미지를 선택한다. 동일하면 대표만 유지하고, 서로 다르면 모두 유지한다.
3. **유사 그룹 확인**: 한 묶음의 여러 이미지를 함께 보고 포함할 이미지를 선택한다. 전체 선택, 기존 기준 그룹 전체 포함/제외, 각각 유지, 판단 보류를 지원한다.
4. **이미지 승인·메모**: 남은 새 이미지는 기본 승인이다. 필요 없는 이미지만 체크를 해제하고, 원하는 이미지에만 자유 메모를 남긴 뒤 **승인 내용 저장**을 누른다.

화면에는 현재 단계만 표시된다. 이전 단계로 돌아갈 수 있지만 후속 단계 승인 표시는 다시 해제된다. 동일 판정을 바꾸면 유사도 판정도 재확인해야 한다. 미판정이 남으면 해당 단계 승인은 차단된다. 기존 기준 이미지의 승인·제외·메모는 이 신규 배치에서 수정하지 않는다.

## 저장과 복원

- 선택·메모는 0.6초 디바운스 후 서버에 자동 저장한다. `서버에 저장됨`이 실제 저장 응답이다. 중간 저장 버튼도 제공한다.
- 자동 저장은 최종 승인이 아니다. 마지막 확정 갤러리는 4단계 승인이 성공할 때만 갱신된다.
- 초안과 승인 이력은 SQLite에 보관한다. 브라우저 새로고침과 서버 재시작 후 이어서 검토할 수 있다. 브라우저 로컬 저장소나 JSON 다운로드에 의존하지 않는다.
- 두 탭에서 동시에 수정하면 오래된 탭의 저장을 차단한다. 최신 내용을 불러오기 전에 미저장 편집을 창 메모리에 보관하고, 같은 단계에서 명시적으로 복원할 수 있다. 이 임시 복구본은 창을 닫으면 사라지므로 경고를 확인한다.
- 응답을 받지 못한 저장은 같은 요청 ID로 재시도한다. 4단계 결정·갤러리·감사 기록은 하나의 트랜잭션으로 확정된다.
- 개인 검토 승인은 재배포 권리나 공개 릴리스 승인이 아니다. 마지막 승인 목록은 이 비공개 관리자 갤러리에서 확인한다.
- 4단계 승인 성공 시 승인 갤러리를 연다. 재접속 시 완료 요약과 **승인된 이미지 보기** 버튼을 표시한다. 좁은 화면에서도 하단 버튼은 유지되며 갤러리 보기는 재승인 요청을 보내지 않는다.

## 이미지 권리 안내

현재 검토 묶음과 승인 갤러리의 모든 이미지에 `rights_display`를 제공한다. 카드의 **출처 · 권리 확인**을 펼치면 출처 링크, 확인된 경우의 제작자, 라이선스 명칭과 적용 범위, 출처 표기와 이용 주의사항을 확인할 수 있다. 확대 보기에도 같은 안내를 제공한다.

- 제작자를 모르면 `제작자 미확인`으로 표시한다. 저장소 소유자나 업로더를 제작자로 추정하지 않는다.
- 저장소 MIT/CC 표시는 개별 이미지의 사용 허가가 아니다. 미확인·이용 제한·개별 이미지 근거 확인을 구분한다.
- 출처 표기는 허가를 대신하지 않는다. MIT 적용 자료는 원문의 저작권 및 허가 고지 유지 조건도 확인해야 한다. [MIT 원문](https://opensource.org/license/mit)
- 표시가 `개별 이미지 근거 확인`이어도 공개 릴리스 승인을 자동 부여하지 않는다. 별도의 사람 검토 증빙이 없으면 미확인 상태를 유지한다.
- 계약: `../00_CORE/schemas/image_rights_notice.schema.json`. 새 image-RAG 인입 manifest는 권리 안내를 포함한다. 기존 동결 manifest/원본은 바꾸지 않고 관리자 응답에 출처 근거를 연결하여 표시한다.

## 승인 후 분석 준비

명시적 `--serve` 시작 시 최신 확정 승인, 그리고 이후 4단계 확정 시 해당 승인에 연결된 후속 작업 자료를 로컬에서 준비한다. 초안 저장과 GET 조회는 준비 작업을 만들지 않는다.

`data/private-research/image-rag-admin/handoffs/`에 승인 commit별 스냅샷, Luna 대기 목록, 텍스트 임베딩 대기 목록, 검증 영수증을 보관한다. 같은 commit은 검증 후 재사용하며 사용자 메모, 유사 그룹, 보관 별칭, 출처·권리, 기존 벡터 참조를 유지한다. 수동 JSON 다운로드/업로드는 필요 없다.

이는 **준비**이며 LLM 실행·새 임베딩·Qdrant 업로드 완료가 아니다. 준비 실패도 이미 저장된 승인 트랜잭션을 취소하지 않으며 화면에 별도로 표시한다. 기존 200개 기준 증분 실행기가 새 스냅샷을 자동 소비하는 기능은 별도 연결 작업이 남아 있다.

2026-09-03 후속 승인으로 최신 handoff 폴더에는 실제 관리자 실행 계정의 읽기·통과 권한, 정확한 JSON 4개에는 읽기 권한만 추가했다. 광범위한 ACL 상속이나 쓰기 권한은 부여하지 않았다. 파일 해시는 불변이며 서버 재시작 후 `/api/admin/handoff`의 `prepared`와 화면의 준비 완료 표시를 확인했다. 앞선 권한 차단 보고는 당시 상태의 기록으로 남긴다.

## 승인 그룹과 원본 프롬프트

승인 목록은 그룹 대표 + 구성원 펼쳐보기이며 그룹 단위로 페이지를 나눈다. 특정 구성원을 검색해도 그 그룹 전체를 보여준다. 현재 확정 379개는 26개 그룹 안의 79개와 개별 300개로 표시된다. 사람의 그룹 결정을 자동 합치거나 임베딩으로 다시 판정하지 않는다. 일부 그룹이 실제로 겹치는 향후 데이터도 원래 그룹을 보존한다.

모든 카드와 확대 보기의 **원문 프롬프트 / 복사**에서 축약된 임베딩 입력이 아닌 해시가 연결된 원문을 가져온다. JSON·공백·줄바꿈·Unicode를 보존하며 클립보드 응답 성공 후에만 성공으로 표시한다. 브라우저가 복사를 막으면 원문 전체 선택과 수동 복사를 제공한다. 원문 확인 실패 시 성공한 것처럼 복사하지 않는다.

화면, 확정 승인 투영, 프롬프트 근거 로더, 로컬 HTTP/SQLite, 배포용 비공개 스냅샷은 분리되어 있다. 배포 준비와 남은 검토의 경계는 `IMAGE_ADMIN_DEPLOYMENT_PREP.md`를 참고한다.

Qdrant는 벡터 저장·검색을 담당한다. 기존 Voyage 이미지 벡터는 재사용한다. 향후 메모/LLM 결과 변경 시에는 변경된 텍스트만 별도로 임베딩하고 이미지 벡터는 다시 만들지 않는 구조로 진행한다. 이미지 파일이나 긴 원문은 Qdrant payload에 복제하지 않고 이미지 ID/그룹/필터와 저장 위치만 최소 보관한다.

## 재실행

이미지 아카이브 디렉터리에서 실행한다. `-Start`가 없으면 검사만 수행한다. 실행 중인 포트를 발견하면 다른 프로세스를 종료하지 않고 중단한다.

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/start_image_admin.ps1
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/start_image_admin.ps1 -Start
```

기존 DB가 있으면 JSON을 다시 넣을 필요가 없다. 첫 실행의 실제 사용자 승인 seed만 별도 인입했다. 운영 DB는 테스트 DB인 `qa-20260903/state.sqlite3`와 다르며, 테스트 DB에는 `SYNTHETIC_QA_ONLY` 메모와 실험 판정이 들어 있다. 테스트 DB를 운영 seed로 사용하지 않는다.

SQLite 백업이 필요하면 실행 중인 `.sqlite3` 파일만 임의로 복사하지 말고 SQLite backup API를 쓰거나 서버를 정상 종료한 뒤 관련 상태를 보관한다. 현재 서버 시작 로그는 `data/private-research/image-rag-admin/runtime/`에 있다.

## 경계와 확장

현재는 동결된 500개 묶음을 관리하는 단일 사용자 로컬 MVP다. 관리자에서 신규 이미지 업로드·수집·임베딩 호출을 하지 않는다. 기존 준비 이미지와 판정 근거를 재사용한다. 새 검토 묶음은 기존 증분 준비 파이프라인으로 동결한 뒤 `-RunId`로 지정한다. UI에서 배치 전환·계정 로그인·외부 접속·Cloudflare 배포는 아직 구현하지 않았다.

Python 표준 HTTP 서버는 인터넷 공개 운영용으로 권장되지 않는다. 따라서 loopback 바인딩, Host/Origin/CSRF 검사, 제한된 미디어 경로만 제공하며 공개 운영은 별도 인증·배포 설계가 필요하다. [Python HTTP server 문서](https://docs.python.org/3.13/library/http.server.html)
